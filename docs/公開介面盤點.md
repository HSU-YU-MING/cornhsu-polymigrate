## 盤點方法

以實際程式碼與實跑結果為準，文件只當對照組。

1. **讀原始碼**：`src/PolyMigrate.Cli/`、`src/PolyMigrate.Core/` 全部 `.cs`，`npm/` 三個檔案，`.github/workflows/release.yml` 的 npm job。
2. **實跑 CLI**（Windows 11、.NET SDK 10.0.302，`dotnet build PolyMigrate.slnx -c Release` 的產物）：
   `--help`、`-h`、無參數、`--version`、`-v`、未知指令、每個子指令加 `--help`，以及各子指令的錯誤路徑。
3. **反射**：拋棄式 console 專案用 `System.Reflection.MetadataLoadContext` 9.0.0 載入
   `PolyMigrate.Core.dll` 與 `polymigrate.dll`，列出 exported types 與 public／protected 成員簽章（含 nullable、`init`、`required`、預設值）。
4. **序列化樣本**：以 `SiteConfigLoader` 同一套 `UnderscoredNamingConvention` 序列化 `new SiteConfig()`，取得 YAML 欄位名與預設值；再餵十二份刻意做壞的 YAML 給 `SiteConfigLoader.Load` 記錄行為。
5. **fixture 實跑**：複製 `tests/fixtures/site` 到拋棄式目錄跑 `extract`／`verify`／`slugs`／`thumbs`，逐檔檢查 BOM、CR／LF、表頭；README 的 YAML 範例與函式庫範例也各實跑一次。
6. **與 v2.3.1 比對**：以拋棄式 worktree 檢出 `v2.3.1` 建置，對兩版做 (a) Core／CLI 反射輸出 diff、(b) `--help` diff、(c) 同一份 fixture 的 `extract` 輸出目錄 `diff -r`；另讀 `git diff v2.3.1..HEAD`。
7. **測試對照**：`dotnet test PolyMigrate.slnx -c Release` 全綠（Core 205、Cli 28）；以 grep 搜尋 `tests/` 確認哪些公開面有測試在守（缺口清單不在本文件）。

拋棄式工具與輸出放在 repo 外的 `_scratch/`，未納入版本控制。

### 2.3 中斷與契約外的結束方式

- `Program.cs:6-24`：第一次 Ctrl-C 設 `e.Cancel = true` 並取消 token；第二次不再攔截，由 runtime 終止行程。只有 `probe-orphans`、`fetch-orphans` 收到 token（`Cli.cs:38-42`），所以 **130 只在這兩個指令可達**；`extract`／`thumbs`／`verify`／`slugs` 第一次 Ctrl-C 沒有作用，第二次由 runtime 結束，**不經 `Cli.Report()` 回 130**；實際結束碼視平台而定：Windows 為 `0xC000013A`（`STATUS_CONTROL_C_EXIT`），Linux／macOS 上 .NET 對未取消的 SIGINT 會還原預設處理並重新送出訊號，行程被 SIGINT 終止，shell 與 CI 看到的是 128＋2＝130（經 npm 啟動腳本執行時同樣是 130，見 2.4）。Unix 這一半依 .NET 的訊號處理行為推得，本機只有 Windows，未實測。
- **實測偏離**：`extract.content`、`extract.type_rules.*.title_selector`、`extract.type_rules.*.remove_selectors` 是不合法 CSS selector 時，config 載入照樣成功，`extract` 在 `PageExtractor.cs:47`／`:62-63`／`:79` 拋出 `AngleSharp.Dom.DomException`，不在 `IsHandled()` 之內 → 未處理例外結束（`content: "section[id"` 與 `title_selector: "h3[["` 兩種都實測過；Windows exit `-532462766`，即 `0xE0434352`）。這不屬於任何契約值。`fetch-orphans` 在抓到第一頁後也會用 `extract.content` 掃資產（`OrphanFetcher.cs:84`），依程式碼同樣不在攔截範圍內（未實測，需要可回 200 的站）。
- 對照組：`extract.strip_title_prefix` 寫錯 regex 時 config 也照樣載入成功，但 `extract` 拋的是 `ArgumentException`，會被攔下 → `error: Invalid pattern ...` → exit 2。

## 7. v2.3.1..HEAD 變更與 semver 判讀

### 7.1 本套件的 semver／凍結規則（摘自 `CLAUDE.md`、`CHANGELOG.md`、`docs/contracts.md`）

- 1.0 起：破壞任一凍結面 → major；新功能 → minor；修正 → patch。
- 讓既有情境的 exit code 改變（含「新增一種 warning」）→ major（`CLAUDE.md`「地雷」段；2.2.1 殘檔回報因此刻意不計 warning）。

- `reject_reason` 是開放集合：新增值 → minor，不必動 `config_version`。
- 函式庫：新增 public 型別／成員 → minor；改既有簽章（包括替既有方法加選用參數，二進位不相容）或收回可見性 → major；相依升級而行為不變 → patch。

- 沒有任何一項需要 minor 或 major。

### 7.5 既有公開面上已觀察到、修正時須先決定 semver 的行為

以下不是 v2.3.1 之後的變更，而是本次盤點時實際量到的公開面行為；修正它們都會讓某一面的可觀察結果改變，所以把歸屬先判好。

| 行為（現況） | 改法 | 判讀 |
|---|---|---|
| 不合法 CSS selector 使 `extract` 以未處理例外結束（exit 非契約值，見 2.3） | 把 `AngleSharp.Dom.DomException` 納入 `IsHandled()` → exit 2 | patch（從契約外回到契約內）。若改成「載入 config 時就驗 selector」，原本能跑的 config（selector 寫壞但從未被用到的 `type_rules`）會開始載入失敗 → 屬 YAML 面的破壞，需 major 或只對 `extract.content` 驗證 |
| `pair_evidence` 的 `date=`、`title_similarity=` 隨機器文化改變（見 3.4） | 改用 `CultureInfo.InvariantCulture` | patch（回到契約範例的 ISO 日期；en-US 等文化輸出不變） |
| frontmatter 行尾隨平台不同（Windows CRLF、其他 LF，見 3.1） | 固定 LF | patch，但 Windows 使用者的 Markdown 位元組會變，CHANGELOG 須附「升級注意」；建議先在 `docs/contracts.md` 寫明 Markdown 行尾（→ 本分支已寫明現況，見「通用規則」） |
| npm 啟動腳本自身失敗回 1，與契約的「1＝warning」撞號（見 2.4） | 改回 2 | **依 7.1 屬 major，留到下一個 major**：現在回的 1 是契約裡有定義的值，既有情境（平台不支援、平台包沒裝、`spawnSync` 失敗）的 exit code 由 1 變 2，正是 7.1 說的「讓既有情境的 exit code 改變」，與下一列 `probe-orphans` 同一把尺。依賴「1＝warning、可繼續」的腳本會把「工具根本沒跑」當成通過，這是要修的理由，但不改變判讀。在那之前可做的 patch：只改 stderr 訊息（改英文、明講工具沒有執行），exit code 不動 |
| `probe-orphans` 在請求全數連線失敗時仍 exit 0 並覆寫 `orphan_slugs.txt` 為空檔（見 2.2） | 加 stderr 警告而不改 exit code → patch；改 exit code → 依 7.1 屬 major | 若要非零 exit，留到下一個 major |
| 8 個 facade 以外的 public 型別（見 5.2） | 收回 `internal` | major；維持現狀則應在文件承認它們是公開面 |
| `<body>` 裡的 `<link rel="alternate" hreflang>` 也被當成作者宣告，進 `hreflang_map.csv` 並參與配對；`ReadAlternates` 的 XML 註解卻寫「`<head>` 裡的」（見 3.5） | 二擇一：(a) 程式改成只看 `doc.Head`；(b) 維持行為，只把 XML 註解與 `docs/contracts.md` 改成「整份文件」 | (a) patch（註解與規劃本意都是 head，HTML 規範也不允許 `rel=alternate` 的 `<link>` 出現在 body），但有這類寫法的站 `hreflang_map.csv` 會少列、配對建議可能改變，CHANGELOG 須附「升級注意」；不影響 exit code。(b) none |
| `slugs` 的 slug 取檔名第一個「.」之前，與 `extract` 不一致（含點檔名印出截斷的 slug，例 `v1`；餵給 `fetch-orphans` 會去抓不存在的 URL）；列表頁 `index` 也列出（見 1.3） | 改用 `extract` 同一套剝尾綴規則；`index` 要不要排除另議 | 前者 patch（現值無法回餵 `fetch-orphans`，屬錯誤輸出的修正；`probe-orphans` 的已知 slug 集同步變正確）。排除 `index` 會讓既有管線少一行輸入，屬既有輸出的刪減，若要做，判讀至少 minor 並在 CHANGELOG 註明；在 diff 流程裡多這一行無害，維持現狀也可 |
| `thumbs` 把多格的 GIF 動畫縮成只剩第一格（`ThumbnailGenerator.cs:48` 以 `MagickImage` 讀檔，只讀第一格；實測兩格 GIF → 縮圖一格、寬 1000）。`docs/搬完之後你還要做的事.md` 在媒體壓縮那一步就提醒過「動畫 GIF 被重新編碼會壞掉」，`thumbs` 卻照樣重新編碼；目前沒有測試或契約寫明現況 | 三擇一：逐格縮放保留動畫、原樣複製、或維持單格並寫明 | 縮圖內容不在四個凍結面之內（`contracts.md` 沒有記載 `media_thumb/`）→ patch；但 `thumbs` 會跳過已存在的縮圖，既有使用者要拿到新結果得先刪掉 `media_thumb/` 裡的 GIF，CHANGELOG 須明講 |

### 7.6 既往版本的判讀紀錄（供凍結紀律參考）

- **2.2.0 的 `PolyMigrator.Verify`、`OutputVerifier.Run` 加了選用參數 `allowUnlinked`**（v2.1.0 為三參數），原本的三參數方法從組件消失：原始碼相容，但已編譯的消費端會 `MissingMethodException`——依 7.1 屬 major，當時以 minor 發出。日後加參數應改用新增 overload。
- **2.2.0 新增 `unlinked_page` warning**，既有使用者可能從 exit 0 變 1；當時以 minor 發出並在 CHANGELOG 標「⚠️ 升級後 verify 可能從 exit 0 變 exit 1」。`CLAUDE.md` 現在的規則把這類變更歸為 major。
