# 搬完之後你還要做的事

> PolyMigrate 的範圍停在「產出乾淨、有契約、可被任何東西消費的中間格式」。
> 但真實的搬遷案在那之後還有一段路。這份文件記錄那段路上會遇到的事——
> **刻意寫成知識而不是功能**。
>
> 判準只有一條：**這件事需不需要用到 PolyMigrate 手上獨有的資料？**
> 需要的（頁面路由圖、語言配對、本地已有的 slug）做成功能；
> 不需要的（壓縮一資料夾圖片、把資料灌進某一套 CMS）寫在這裡。
> 把外面工具就能做的事吃進來，只會讓工具的邊界糊掉、契約變得不穩定。
>
> 數據來自香雲寺全站搬遷（584 頁、雙語、2,231 個媒體檔）。

---

## 一、把媒體壓成適合網頁的尺寸

`polymigrate thumbs` 產生的是**額外的小預覽圖**（`media/` → `media_thumb/`），原檔不動。
但搬完幾乎一定還要做另一件事：**把原檔本身換成適合網頁的尺寸**。

### 值不值得做

香雲寺的實測：

| | 檔數 | 大小 |
|---|---|---|
| 原檔（相機直出，最大 8256×5504） | 2,231 | **4.92 GB** |
| 網頁版（長邊 1920 / JPEG q82 / 去 EXIF） | 2,231 | **1.19 GB（24%）** |

4.92 GB 直接上雲的代價是實的：儲存費、部署時間、前台載入速度。
而在本案的上傳頻寬（實測 1.5 Mbps）下，這個差別是 **7 小時 vs 1.8 小時**。

### 最重要的一條規則：檔名不能變

壓縮後**檔名與相對路徑必須完全一致**，Markdown 裡的媒體引用才不用改。

這也是**不建議轉 WebP** 的原因——副檔名一變，所有引用都得跟著改。
香雲寺實測：JPEG 佔 96%，轉 WebP 大約再省 25–30%，
但要重寫 2,172 筆引用，投入與收益不成比例。

### 五條從實作中學到的規則

1. **壓完反而變大就用原檔**——小圖、已經優化過的圖很常見（本案 51 個）
2. **EXIF 轉正之後再存，並且去除 EXIF**（含 GPS 等個資）
3. **非圖片一律原樣複製**（mp4、PDF、GIF 動畫——動畫 GIF 被重新編碼會壞掉）
4. **失敗時退回原檔，不要跳過**——寧可大也不能缺
5. **輸出到另一個目錄**（`media_web/`），原檔是唯一保存檔、隨時可以重產

### 做法

規則 1、3、4 是一行指令做不到的，但一小段 bash 就夠：

```bash
cd media
find . -type f | while read -r f; do
  out="../media_web/$f"
  mkdir -p "$(dirname "$out")"
  case "${f,,}" in
    *.jpg|*.jpeg|*.png)
      magick "$f" -auto-orient -resize '1920x1920>' -quality 82 -strip "$out" 2>/dev/null
      # 壓失敗、或壓完反而比原檔大 → 一律退回原檔
      if [ ! -s "$out" ] || [ "$(stat -c%s "$out")" -ge "$(stat -c%s "$f")" ]; then
        cp "$f" "$out"
      fi
      ;;
    *) cp "$f" "$out" ;;
  esac
done
```

- `1920x1920>` 的 `>` 是「只縮不放」，所以本來就小的圖不會被放大糊掉
- `-auto-orient` 要在 `-strip` 之前：先依 EXIF 轉正，再把 EXIF 丟掉
- `stat -c%s` 是 GNU 版；macOS 用 `stat -f%z`

跑完之後把 `media_web/` 當作要上傳的那一份，`media/` 留著不動。

### 為什麼不做成 `polymigrate optimize`

因為 PolyMigrate 在這件事上**沒有任何資訊優勢**。壓縮 `media/` 只需要
「一個裝滿圖片的資料夾」——不需要路由表、不需要連結圖、不需要語言配對。

而要付的代價是實的：新增一份 Phase 輸出契約、一組跨平台會飄的圖片比對測試
（不同機器上的編碼結果不保證位元一致），以及讓「i18n 搬遷器」這個定位
多長出一隻做維運雜工的手。

## 二、把內容灌進 CMS

香雲寺後來把內容灌進 Umbraco，寫了約 1,000 行的匯入程式。

**那 1,000 行不會進 PolyMigrate**，因為它幾乎全是 CMS 專屬的：內容類型、資料型別、
語言變體、發布快取——換一套 CMS 就要整個重寫。把某一套 CMS 的知識放進來，
會讓工具的邊界糊掉，也讓對外契約變得不穩定。

### 你手上有什麼

匯入程式要吃的東西，PolyMigrate 已經全部備好了：

| 檔案 | 給匯入程式用來做什麼 |
|---|---|
| `content/**/*.md` | 正文與 frontmatter，一頁一檔 |
| `content_inventory.csv` | 全站清單：每個 `translation_key` 有哪些語言、配對狀態、頁型、flags |
| `media_manifest.csv` | 每個媒體檔的本地路徑、原始網址、被誰引用、SHA-1、大小 |
| `redirect_map.csv` | 舊網址 → 新路徑（另有 nginx 與 `_redirects` 兩種現成格式） |
| `missing_images.csv` / `need_fetch_media.txt` | 已知缺件，匯入前先決定怎麼處理 |

frontmatter 的欄位契約見 [contracts.md](contracts.md)，**自 1.0 起穩定**。

### 匯入程式大致長什麼樣

不論哪一套 CMS，順序大致相同：

1. **先建媒體，拿到 CMS 給的 ID**——正文引用要改寫成這些 ID 或新網址，
   所以媒體一定要先於內容。`media_manifest.csv` 的 SHA-1 可以用來跳過重複上傳。
2. **依 `translation_key` 分組建立內容**，一組 = 一個內容項目的所有語言版本。
   先建預設語言，再掛其他語言變體——多數 CMS 的語言變體是掛在同一個節點下的。
3. **`page_type` 對應到 CMS 的內容類型**（article / event / listing / page）。
4. **`flags` 是給人看的待辦**，不是資料：`needs_rebuild` 表示那頁的版面在舊站是硬幹出來的、
   搬過去要重做；`text_in_image` 表示資訊鎖在圖片裡，需要人工補文字。
   **不要讓匯入程式自作聰明地處理它們。**
5. **最後才部署轉址表**，並且要在 DNS 切換之前就驗過。

### 先跑一次 `verify`

匯入之前先讓 `polymigrate verify out/` 是乾淨的。它是離線的契約完整性檢查——
壞連結、缺媒體、缺欄位、沒有任何頁連到的孤島頁，全部在灌進 CMS 之前就會知道。

## 三、上線之後

### 全站巡檢抓不到「沒有入口」的頁

上線後跑一次全站巡檢是必要的，但要知道它的盲區：**巡檢是沿著連結走的**，
走不到的頁根本不會被走訪。香雲寺上線後巡檢 584 頁回報 0 錯誤，
而實際上有一頁（BLIA Austin）完全找不到——它是頂層頁，沒有任何頁連到它，選單也漏了它。

「零錯誤」在這裡是誤導：它證明的是「連得到的頁都正常」，不是「所有頁都正常」。

這一類現在由 `polymigrate verify` 的 `unlinked_page` 警告覆蓋（2.2.0 起）。
但注意它的界線：**選單不在 Phase 2 輸出裡，verify 看不到**，
所以它能斷言的是「沒有任何內容頁連到它」，不是「完全沒有入口」。
選單本身要人工核對。

### 舊站不會停止更新

新舊站並行期間舊站會繼續發文，必須反覆同步到 DNS 切換為止
（香雲寺這段期間多了 4 篇新聞、1 個活動）。

```bash
polymigrate slugs . --section news > local.txt     # 「.」= 放 raw/ 的那一層
# oldsite.txt：由你自己的腳本產生，去舊站列表頁挑出現在有哪些 slug
comm -13 local.txt oldsite.txt > missing.txt
polymigrate fetch-orphans site.yaml --section news --slugs missing.txt
```

「去舊站讀列表頁」這一半刻意留給你自己的腳本，因為它每個站都不一樣——
香雲寺的活動根本沒有列表頁（`/ch/events/index.php` 回 404，是從首頁卡片連出去的）。

**寫這支腳本時記得兩件事**：

- **抓到 0 筆要當成錯誤，不是「沒有新文章」。** 舊站一改版、選擇器抓不到東西，
  排程會每天乖乖回報「沒有新文章」，而你以為在追平，其實早就斷線了。
- **它跟 PolyMigrate 一樣是在抓一個你有權搬遷的站。** 併行期會反覆去打舊站，
  記得留禮貌間隔——`site.polite.delay_ms` 是給 PolyMigrate 自己用的，你的腳本得自己節流。
